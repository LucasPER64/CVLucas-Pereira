Les informations liées aux clients et les identifiants ont été masqués pour respecter leur confidentialité.

Rapports enregistrés dans PostgreSQL

Voici le type de rapport enregistré après une exécution. On y retrouve les horaires, les volumes et nombres de fichiers à la source et à l'arrivée, le statut et le journal associé.

Connexion à PostgreSQL depuis PowerShell

Le script interroge PostgreSQL pour récupérer les paramètres utiles à chaque sauvegarde, puis y enregistre le rapport une fois le traitement terminé.

Export Hyper-V (PowerShell)

Cet extrait lance l'export d'une machine virtuelle à partir des paramètres récupérés dans la base. Le même principe permet d'adapter le script à plusieurs environnements.

Automatisation et planification des tâches

Les sauvegardes sont lancées à heure fixe, puis contrôlées régulièrement sans intervention manuelle.

  • Windows : le Planificateur de tâches déclenche les exports Hyper-V, les sauvegardes et les copies Robocopy.
  • Linux : Crontab lance les contrôles et le reporting sur le poste de sauvegarde interne.

Email d’alerte (supervision)

En cas d'anomalie, l'email précise ce qui doit être vérifié : taille insuffisante, délai dépassé, fichier manquant ou erreur d'exécution.

Stockage sur le poste interne Linux

Les sauvegardes sont rangées dans une arborescence stable afin de retrouver rapidement un client, une machine et une date de sauvegarde.
